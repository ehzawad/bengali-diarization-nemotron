**External evaluation, data availability, and licences — checked 2026-09-26**

The search found additional Bengali audio with speaker-related annotations, but **no immediately verified, openly downloadable natural gold diarization corpus that can safely be declared an independent Nemotron hold-out**. This is a bounded search result, not a claim that no such dataset exists. There are promising conditional routes: licensed Babel conversations, obtaining the older NSU annotations, or creating fresh human references. DISPLACE has real diarization labels but is already named in the pinned base model's training inventory.

“Available,” “labelled,” and “clean” are different requirements. A useful final set needs accessible audio, legitimate use rights, human speaker/time labels of known policy, independence from our selection history, and an upstream overlap assessment. A dataset card or a speaker-ID column alone does not satisfy these requirements. Unknown pretraining exposure should be recorded as unknown, not silently promoted to absent.

**Kaggle: what is verified and what remains unverified**

The indexed official [leaderboard](https://www.kaggle.com/competitions/dl-sprint-4-0-bengali-speaker-diarization-challenge/leaderboard) displays a late-submission entry point, completed standings, approximately 71% private test data, and a leading score of 0.25573. Direct HTTP retrieval saved only the JavaScript shell; these facts were verified through the search tool's indexed rendering of the official page. No authenticated endpoint, notebook, submission, or returned score was tested. A visible button is evidence of an advertised option, not proof that this account can currently obtain both scores.

The [competition overview](https://www.kaggle.com/competitions/dl-sprint-4-0-bengali-speaker-diarization-challenge) distinguishes the online public/private evaluation from a further final-round hidden test. It also describes a transformed performance score, whereas the leaderboard presents DER-like decimals. Archive the server's actual metric name, value, partition, and scoring implementation before interpreting a result. Collar, overlap handling, aggregation, and reference cleaning must not be guessed from our local scorer or from the generic DER formula.

For this project, a rigorous late evaluation means freezing both primary base/FT systems, their prediction files, and the comparison before any score is viewed. A single frozen system's score supplies a held-out benchmark observation; it does not establish an adaptation benefit. Two predeclared arms can establish an aggregate point difference on the returned partition. Without recording-level errors, they cannot supply our desired paired recording-level uncertainty, error decomposition, or evidence that most recordings improved.

If the service returns both scores, use private as the prespecified primary partition and public as secondary. If it returns only public, report only public and leave the private endpoint unobserved. Do not infer that 71% means exactly ten files, 71% of duration, or 71% of reference speaker-time. Do not combine public/private DER using 0.29/0.71 weights without knowing the scorer's denominators. The [CUET system paper](https://arxiv.org/html/2602.21741v1) reports 20.936% public and 27.671% private DER, a 6.735-point difference: the distinction can change the interpretation materially.

After the first result informs any redesign, that partition becomes development feedback. A “private” name does not prevent repeated late submissions from overfitting it. Do not claim a historical competition placement, prize eligibility, an official final-round outcome, or an equal-era comparison for a model released after the competition. Local 26.97% development DER and another team's 27.67% private DER are not comparable measurements of the same endpoint.

A late benchmark score also does not certify upstream training independence. The checkpoint postdates the competition, its full media-level training inventory is unavailable, and published solutions have already supplied community feedback about this benchmark. None of that proves test contamination, but it prevents a stronger claim that this is wholly new, previously unstudied audio for every part of the system. Use “held out from this project's adaptation and selection” unless source-level provenance supports more. Fresh recordings can address this limitation more directly.

The [rules](https://www.kaggle.com/competitions/dl-sprint-4-0-bengali-speaker-diarization-challenge/rules), sections 4–5 and 11, prohibit manual test annotation and test-derived external data, require reproducible Kaggle inference, and restrict external infrastructure to training. They require disclosed model provenance. See the operational interpretation in [02-final-protocol.md](02-final-protocol.md). In particular, this research design does not authorize a submission or imply that local GPU inference already meets competition submission requirements. The owner's existing no-submission ruling remains in effect.

**Release licences and provenance**

The pinned Nemotron README declares OpenMDW-1.1, and the checkpoint hash matches the local base model. The [OpenMDW text](https://openmdw.ai/license/1-1/) grants broad use/modification/distribution rights with notice and agreement obligations. A missing standalone `LICENSE` at that HF revision returned 404 in this audit; it does not erase the card's explicit licence. The pinned [WeSpeaker card](https://huggingface.co/pyannote/wespeaker-voxceleb-resnet34-LM/blob/837717ddb9ff5507820346191109dc79c958d614/README.md) declares CC BY 4.0 for its weights. Retain both components' provenance and applicable terms; “all weights MIT” is unsupported.

Original project code may be released under MIT if its own provenance permits. A repository containing multiple components should identify their licences separately. A public model package needs the exact base revision, modification notice if fine-tuned, relevant agreement/attribution material, embedding dependency and licence, and the training-data use basis. Training-data restrictions are not automatically identical to model-weight restrictions; assess the actual terms rather than assuming either that every restriction disappears or that every source licence automatically attaches unchanged to the weights.

The [Bengali-Loop paper](https://arxiv.org/html/2602.14291v1), release discussion, distinguishes public-media source rights from distributable annotations/manifests. I did not verify a blanket right to relicense all source audio under MIT. The private core repository avoids some distribution acts but is not itself a licence analysis, and a public HF checkpoint remains a separate release. Prefer links/manifests over bundling source audio until rights are established. No acceptance, purchase, correspondence, upload, or release was performed by this role.

**Availability evidence and its limits**

`evidence/web/manifest.json` contains timestamped HTTP results, final URLs, byte counts and SHA-256 hashes for the initial public retrievals. Raw model cards, dataset API inventories and selected papers/terms are saved next to it. Kaggle's saved HTML is only a shell; the observations above rely on indexed official text, whose crawl date may precede this audit. Public catalogue pages and a terms PDF demonstrate a documented acquisition route, not entitlement for the current user. A failed anonymous raw fetch establishes an access limit for this audit, not that a dataset is unavailable to an approved account.

Decisions left open are access to LDC or the NSU data, rights clarification where metadata and terms differ, budget for fresh annotation, and explicit owner authorization plus eligibility for any late submission. These dependencies do not prevent an honest development-set report now.
