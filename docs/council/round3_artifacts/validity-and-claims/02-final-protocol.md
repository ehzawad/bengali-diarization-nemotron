**Prospective final protocol — proposed, not executed**

The most rigorous use of the remaining budget is to freeze a small comparison and reserve compute for independent evaluation. The constraint is access to trustworthy new labels, not a lack of GPU cycles. Keep the phase-3b base-weight pipeline as the incumbent until another candidate meets a stated development criterion. A clean evaluation may legitimately return “inconclusive”; do not spend the reserve trying to change that conclusion after seeing it.

**1. Freeze the question and the resource boundary first**

Primary scientific question: does the selected Bengali-Loop fine-tuning recipe improve full-system diarization over base weights when both systems receive the same available decoder calibration? Primary practical endpoint: corpus DER difference FT minus base on one specified independent corpus and reference policy. This tests the delivered systems, not every possible form of fine-tuning. A paired common-decoder comparison is a secondary control for attributing differences to weights rather than calibration choices.

Assumption for the recommended new-recording branch: the practical target is acoustic speech diarization. Its primary outputs retain native subsecond boundaries and gap fill 0; a pause-inclusive benchmark view is secondary. Under a separately authorized Kaggle branch, the primary target instead follows the independently documented benchmark reference and scorer. The latter can legitimately use a convention adapter. This branch/target choice must precede access to new reference labels and results and cannot be selected by which produces the more favorable headline. The acoustic counterpart is a new prospective configuration; it is not the existing gap-5 incumbent to which the historical 26.97% applies.

The earlier ledgers contain 13,825.607 s for phase 2, 5,782.273 s for phase 3b, and 89.688 s for the two final demos. The demo ledger duplicates the final ledger and must not be counted twice. `docs/phase3b_results.md:240–247` gives 5.741 cumulative GPU-hours including earlier work. Our role used zero. Reconcile all other council and probe work before execution; the report's historical total is not a live global accountant.

Set the new cap to **min(5.5 hours, 12 − verified cumulative GPU-hours − 0.25 hours reserve)**. At 5.741 prior plus a fully spent 0.5-hour council allowance, 5.5 more leaves about 0.259 hours. If the ledger is incomplete or other work has already spent this allocation, reduce the plan. Never assume the full nominal six hours remain independently for each role.

| Work item | Maximum additional GPU-hours | Purpose and stopping rule |
|---|---:|---|
| One bounded development challenger and matched base/FT caches | 1.50 | One medium-session candidate and/or one selected linker implementation; reuse all existing probability/embedding caches and inner models. Stop before adding a new family. |
| Final all-ten FT models, if the scientific FT contrast is retained | 0.35 | Primary seed 42, plus seeds 43 and 44 only for predeclared robustness; fixed recipe and horizon, no seed selection. |
| One independent evaluation batch | 1.50 | Base and FT predictions, with shared caches for convention variants. Priority over optional baselines. |
| One external baseline, only if already accessible and runnable | 0.75 | A frozen off-the-shelf comparison; no new adaptation/search. Otherwise leave unused. |
| Packaging, output validation, runtime/memory reproduction | 0.40 | Correctness and resource reporting without label-driven changes. |
| Failure/recovery contingency | 1.00 | Actual failed jobs and deterministic engineering repair; not another search allocation. |
| **Total ceiling** | **5.50** | It is acceptable and preferable to finish below this cap. |

These are caps, not measured guarantees for unrun architectures. Existing medians are about 98 s per 165-step fit and the two end-to-end 40–56-minute demos took roughly 42–47 s (`evidence/artifact_audit.json`; `docs/phase3b_results.md:152–157`). That makes a small final comparison plausible, but a longer session or different clusterer may change runtime. Run the first development recording as the timing pilot, extrapolate, and reduce optional work before consuming the evaluation reserve. No pilot on new labelled hold-out data.

All GPU work must use `scripts/gpu_run.sh`, one card, with an explicitly checked ≤20 GB memory cap. The wrapper serializes allocation; it does not itself enforce the memory limit or total budget. Log successful and failed GPU lock-holding time, card, command, outputs, and peak allocated/reserved memory. CPU work uses the specified environment and at most four workers. During this council, implementation and output paths remain under the authorized `/tmp` directory; repository mutation is not part of this role's protocol execution.

**2. Bound development; do not try to create a new test fold from the old ten**

All original ten recordings remain development data, including all previously “outer” examples. Preserve the original folds for comparability and continue using inner predictions that exclude both the scored recording and its outer fold. Retain those exclusion checks for any new medium-session inference. Avoid inference with an all-ten-trained model for development ranking.

The frozen incumbent is base weights with `s20_avg_g5_a0.40_c0.60`. Allow a maximum of **one challenger package** from the architecture/linking lenses, with complete settings and code hashes supplied before final scoring. A concrete medium-session test is 180 s cores plus the existing 5 s context on each side, alongside the 20 s control. A concrete adaptive-linking test is the lens's one fixed NME-SC implementation alongside the current average-linkage control. If those changes are combined, the **combined package must be tested on development predictions**; separate individual gains do not validate their interaction. If no fully specified package exists by the cap, use the incumbent.

For the new package, preregister a small, symmetric local calibration family: θ_act ∈ {0.25,0.40}; gap fill ∈ {0,5} s; for cosine AHC θ_clu ∈ {0.55,0.60,0.65}. For an adaptive clusterer, use one fixed parameterization chosen by its lens rather than pretending a cosine threshold is transferable. Boundary flooring is a separately reported adapter; do not multiply the architecture search by shifts/rounding variants. The historical 80 s cache can be reported as a sensitivity, not repeatedly reopened to chase the best architecture. Testing gap >5 s or new PLDA training is deferred unless it replaces, rather than enlarges, the one challenger and is fully frozen up front.

For each arm, calculate calibration choices from its eligible inner predictions with the same family and rule. Restrict the acoustic primary selection to gap 0 and native boundaries; gap 5 remains a diagnostic and a candidate for the benchmark-target branch. A simple prospective operational rule is: select the simplest candidate within **0.5 pp pooled inner DER** of the minimum. Use this lexicographic tie order: incumbent architecture before challenger; 20 s before 180 s; average linkage before the fixed adaptive linker; gap 0 before 5; θ_act 0.40 before 0.25; AHC θ_clu 0.60 before 0.55 before 0.65. Omit dimensions absent from a branch. This avoids calling the earlier weighted/unweighted “1-SE” heuristic an inferential bound. It is a new prospective decision rule, not a retroactive correction of phase 3b. Report historical results under their original rule unchanged. As before, a final joint mode across folds is a development selection; resolve mode ties by the same order, report stability, and never use its same-data DER as final validation. Calibration against coarse development references is itself a limitation for the acoustic target; keep that fact visible instead of tuning on the new acoustic test.

Decide whether to adopt the challenger using a fixed development criterion, such as at least 1 pp corpus improvement and no more than a 10% increase in summed speaker-count absolute error relative to the incumbent, with no reference-driven recording-specific exceptions. These are operational thresholds, not significance claims. Keep a table of all proposed/tested/rejected systems and the reason for rejection. The clean evaluation is then one predeclared comparison, not a tournament of whatever survived many undisclosed experiments.

The existing FT recipe is a constrained test, not an exhaustive adaptation search. Use the already chosen high-learning-rate recipe and disclose it. For a final all-ten model, a concrete frozen choice is lr 5e-5, timing shift estimated from all ten development recordings, gap-5 trusted spans, the same partial unfreezing, 165 steps, seed 42. Seeds 43/44 are robustness replications of exactly that recipe. Do not choose raw versus shift, horizon, seed, or checkpoint using the clean set. All-ten 165-step exposure differs from the earlier six/eight-recording fits; disclose this rather than imply identical effective epochs. These final FT fits are new research comparators; they do not automatically override phase 3b's base default. Do not publish an all-ten model as though it has the OOF scores of the eight-recording refits.

**3. Acquire independence outside the GPU budget**

Preferred route under the existing no-submission ruling: a new, provenance-checked, human-labelled set. Either obtain a previously unseen licensed dataset with validated diarization annotations, or commission consented Bengali recordings. The availability audit in [03-external-data-and-licences.md](03-external-data-and-licences.md) finds no immediately verified, unrestricted, natural Bengali gold set that is also demonstrably absent from upstream training. DISPLACE is explicitly unsuitable for the latter purpose. Babel is a conditional acquisition/conversion route, not already downloaded gold RTTM.

For a new in-domain final set, target **at least 12 independent recordings/source groups, roughly 4–6 hours total**, including several 20–40-minute recordings, recurring speakers after long gaps, short-turn participants, and some sessions with more than eight distinct speakers. Include quiet dialogue and music/noise conditions. Recruit distinct participants/source groups where feasible; avoid all recordings being episodes featuring the same actors. These are design targets, not a power guarantee. Prefer recordings created after the pinned checkpoint release, with consent and documented rights. This can establish provenance far more strongly than another arbitrary public-media download.

Human annotation is an additional money/time requirement that six GPU-hours do not cover. If only two hours across a few recordings are possible, retain the evaluation but describe it as a pilot with correspondingly broad uncertainty. Do not call many clips from one recording many independent tests. A two-speaker telephone corpus can establish cross-domain performance on that setting, but cannot validate long-form >8-speaker linking. A synthetic corpus may separately exercise that capacity; its result must remain separately named.

Have an evaluator/annotator receive the frozen file list and policy, without system outputs, model identity, or which alternative is expected to win. Create native-resolution speaker identity and acoustic activity labels, explicitly marking overlap and uncertainty. Predefine audible breath/nonlexical speech, internal pause, music/singing, background speech and speaker-return handling. Double-annotate a random 20–25% subset distributed across all source groups, then adjudicate disagreements blind to model predictions. Report inter-annotator disagreement and excluded/uncertain duration. Whole files should be scored wherever feasible; if only sampled intervals are annotated, choose the intervals before inference and use an explicit UEM. Do not extrapolate sampled-window DER to whole-recording speaker linking without evaluating long-range identity consistency.

For the convention hypothesis, create **two independent target views on the same new audio**: acoustic intervals with overlap, and a separately specified pause-inclusive/single-speaker turn policy. Keep the fine-resolution source labels and provenance. A deterministic floor/coarsening of acoustic labels is a useful controlled intervention but is not an empirical observation of how Bengali-Loop annotators worked. Likewise, new labels on the old ten support mechanism analysis but remain development material. Do not manually label Kaggle test audio as a substitute while claiming competition-rule compliance.

A blinded label custodian should retain references until predictions and system hashes are frozen. A human need not hide the general annotation policy—that is part of the task—but must hide example-specific labels and scores. Do not inspect outputs to decide which recordings qualify. Apply predetermined eligibility rules, log every exclusion, and count failed inference according to a predeclared policy instead of silently dropping hard files.

**4. Freeze artefacts before independent inference/evaluation**

Write a timestamped manifest containing: dataset/source IDs and waveform hashes; recording/source-group membership; model/revision and file hashes; code/environment hashes; selected configurations; all FT seeds; training recording sets; scorer version, UEM, reference conversion and overlap policy; primary metric; comparison direction; tolerances and tie rules; compute limits; the complete output list; and the rule for failures and any technical rerun. The local phase freezes are helpful; for a paper, an independently timestamped protocol or immutable hosted copy strengthens the record. A new preregistration governs future data only; it does not cleanse earlier exposures.

Freeze all final predictions before seeing any new score. Include base and primary FT, optional seed replicas, and any predeclared convention controls in the same frozen batch. Keep per-channel probabilities, native boundaries, track identities, and final RTTMs so postprocessing changes can be reproduced without another neural pass. Retain a distinct benchmark adapter output; never overwrite acoustic output with snapped times. Use one hashed scoring-reference version for every arm.

Minimum factorial diagnostic for convention learning: base/FT × gap {0,5} × timing {native,floor}, with a common fixed architecture and common decoder parameters. These eight outputs mostly reuse cached neural predictions. The practical primary pair may additionally use each arm's preselected calibrated decoder, but label that as the whole-system comparison. Do not select the primary pair from the factorial results on new labels.

For each reference view, report the paired FT effect without the adapter, the paired FT effect with the adapter, and the difference between those effects. A much smaller FT advantage under convention matching supports the proposed explanation. Stronger evidence comes from the interaction with reference policy on independently labelled audio. It still does not prove FT learned exclusively conventions. Reference strata, boundary distances, and low-VAD-probability strata should be predeclared secondary diagnostics, not used to redefine the primary population after results.

**5. Score once and match the claim to the result**

For a new fine-resolution set, primary scoring should specify whole-file UEM, overlap treatment, one recording-level Hungarian mapping, and collar 0. Report 0.25 and 0.5 **total-width** collars as sensitivities, not a search for the best result. For a benchmark-style set, keep the benchmark's independently documented primary metric; report our scorer separately if parity is unknown. For true overlap references, also preserve/report a multi-label acoustic output or explicitly state that the exclusive product output cannot express overlap. Do not change reference overlap policy to help an exclusive model.

Report corpus DER with MISS/FA/CONF, macro recording DER, every recording's paired delta, speaker-count absolute error and signed bias, plus a predeclared minority-speaker measure. Evaluate runtime, peak memory, and failures on the final system, not just the neural backbone. End-to-end global clustering and same-speaker gap filling use future information; describe the pipeline as offline unless latency/revision behavior is separately established.

Resample **independent recording/source groups** for paired corpus-DER intervals. If the new set's groups are independent, 50,000 fixed-seed bootstrap draws are sufficient for numerical reproducibility; the number of draws does not fix a small corpus. Show leave-one-group-out sensitivity and per-group results. Training seeds are repeated realizations, not new recordings; show their range separately and keep seed 42 primary. Do not create an artificially large n by pooling seed×window observations. An optional paired randomization/sign test must use the same independent unit and be described as such.

For the primary superiority claim require a predeclared practically meaningful margin (e.g. observed improvement ≥1 pp) and an interval excluding zero in the beneficial direction, plus disclose heterogeneity and worst regressions. If the interval crosses zero, say “inconclusive/no demonstrated benefit on this test.” To claim practical equivalence, set an equivalence margin before testing (e.g. ±1 pp) and require a suitable equivalence interval wholly inside it; the current interval fails this by a wide margin. No power guarantee is possible from “six GPU-hours.” If several contrasts are promoted to confirmatory claims, predefine multiplicity control or a fixed testing hierarchy; otherwise mark all but the one primary comparison exploratory.

After the score release, preserve the batch regardless of which system wins. A scoring or serialization bug can justify a logged technical correction applied to all affected arms with old and corrected results retained. Changing thresholds, seeds, session lengths, floor rules, eligibility, or endpoints because of the result consumes the hold-out; any later system needs another independent confirmation.

**6. Unlabelled Kaggle audio and a conditional late-evaluation branch**

Fixed audio loading, sample-rate checks, hashing, runtime/memory profiling and prediction generation are legitimate operational uses without labels. Record the existing `test_029` exposure (`docs/phase3b_results.md:150–161`). Predetermined per-recording clustering or normalization is part of an ordinary inference algorithm, even though it estimates recording-specific nuisance quantities. It is not the same as estimating one test-wide calibration and choosing it after inspecting test outputs.

Pooling test audio for self-supervised training, pseudolabel training, domain adaptation, threshold estimation, or hand-guided architecture selection changes the estimand to transductive adaptation. Hidden labels can still evaluate a legitimately allowed frozen transductive method, but that is not an inductive untouched-audio test. For this project it would also deviate from the original no-test-selection rule. The audited competition rule creates a further restriction on test-derived data; permissibility cannot be inferred merely because labels are hidden. Our recommended final branch uses **no test-set learning**. No manual listening-derived corrections, speaker-count hints, or hand labels enter a compliant submission.

An independently frozen, blinded reannotation of previously unlabelled test recordings could be scientifically informative in a separate offline study. It is not automatically authorized by the files being downloadable or by the competition ending: first establish the applicable data-use terms and permission to depart from the no-test-annotation rule. Report it as a new reference set, never as Kaggle's hidden reference, and keep any resulting adaptation outside a supposedly untouched competition evaluation. Existing output exposure of `test_029` must be disclosed; exclude it from a strongest untouched-audio claim. No such permission was verified or annotation undertaken here, so this is a conditional fallback, not the recommended immediate route.

A late Kaggle evaluation is optional and requires an explicit change to the owner's no-submission ruling; it is **not authorized by this audit request**. If later authorized, freeze at least the base and FT primary predictions before any submission, then submit the whole predeclared batch without using early-returned scores to alter later files. One submission of the final winner cannot establish the causal FT comparison. Two scores allow a paired-system point comparison on a common partition, but server aggregates alone do not yield a valid recording-bootstrap interval or per-recording error attribution. Prefer an organizer-run frozen batch with per-recording components if available, without sending any request in this run.

Retain the raw returned score and partition label. Report public and private separately; choose private as the primary online endpoint **before** looking, only if late submissions actually return it. If only a public score is returned, the primary private endpoint remains unavailable; do not quietly substitute public as confirmation. Do not average scores using 29/71 as weights unless the official denominator/aggregation proves that operation valid. The separate final-round hidden test is a third evaluation stage, not the private leaderboard. Details and verified availability are in [03-external-data-and-licences.md](03-external-data-and-licences.md).

**7. If independent data remain unavailable**

Finish a base-weight pipeline/configuration release, clearly named development evaluations, a provenance and licence record, and the matched convention controls already available. Reserve the independent-evaluation budget rather than spending it on more ten-recording sweeps. A narrow empirical paper can present a reproducible baseline-reversal case study, with external validation explicitly absent. The final claims should say that new-data performance and a general acoustic convention-learning mechanism remain unconfirmed. This is a complete, honest outcome under the constraint, not a reason to manufacture a hold-out from previously examined files.
